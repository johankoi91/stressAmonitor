# sample_send_h264_pcm 参数核对

核对日期：2026-11-23（Asia/Shanghai）。

## 版本与证据范围

- 对象为本仓库及 81.71.150.26 上 rtc-stress 容器中的同一份 Linux amd64 二进制。
- SHA256：`79ecd7f341f1f6720e126936eab0899eeb888e8a0fddffa917d28984bc7fd7af`。
- ELF Build ID：`6789435aa3bfe45f85dff35b8a4f50d2b4f87753`，保留函数符号，没有找到对应 C++ 源码或 DWARF 调试信息。
- 从二进制参数表提取 31 个长参数（含一个连接分隔符），实测全部参数和 30 个带值短参数别名。
- 共 180 次离线参数解析检查：50 次基础及组合、100 次边界及非法输入、30 次短参数别名。
- 检查在临时容器 `--network none` 中执行；故意缺省 token 或 cname，使程序在建立 SDK 连接之前退出。因此配置打印后的退出码 255 在这些探测中是预期结果，不代表该参数无效。
- 行为结论另结合该版本的参数解析器、main、连接创建、发送、订阅和 MainTimer 的反汇编；完整收发、鉴权、网络协议和性能没有实测。
- 原始输出：`sample-parameter-audit/parser-results.json`、`validation-results.json`、`short-results.json`。反汇编临时文件在 `/tmp/rtc-stress-parameter-audit/disassembly.txt`。

## 命令语法及作用域

长参数使用 `--uid=10001` 形式；`--uid 10001` 不被该版本识别。短参数使用 `-I 10001`；`-I=10001`、`-I10001` 不被识别。

`-O` 或 `--next-channel` 创建下一条连接配置。它表示同一进程内的下一条连接，不要求进入不同频道。每条连接重新从默认值开始，不继承上一条的 token、频道、角色、AP、媒体文件和订阅配置。末尾多一个 `-O` 会额外创建一条空配置，并导致缺少 token/cname 的检查失败。

全局配置只有一份，跨 `-O` 生效。实测前面 `--video-rate=15`、后面 `--video-rate=25` 时，全局值最终为 25。普通标量重复赋值以最后一次为准，extra 参数则追加。

`LD_LIBRARY_PATH` 是环境变量，不是本程序参数。`nohup`、重定向、`&`、`echo $!` 均为外层 Shell 行为。

## 会影响现有脚本和页面的发现

### Meeting 页面实际生成的是观众

`stress_huge.py` 的 UserBase 把 `_role` 固定为 1。与当前二进制结合后，程序创建观众角色，main 仅在 role=0 时创建发送轨道、初始化发布并启动发送线程；InitializePublish 和 StartSendThread 内部也会跳过 role=1。

因此即使网页设置了媒体文件、pub_audio、mute 或 dual，不能据此认定这些用户在发流。之前依据 Python 参数所作的“可以发布”描述不够准确，应以 Native 的角色分支为准。这是代码行为核对，尚未做真实 RTC 收发验证。

另外 stress_huge.py 的 UserBase 接收 sub_video_high 参数后，把 `_sub_video_high` 直接设为空字符串，导致调用侧计算出的大流订阅 UID 丢失；小流列表则保存。需要与参数合同一起修正和验证。

### 页面变量 render 名称不准确

meeting_container_server.py 的 STREAM_DEFAULTS 用 `render` 命名 `-R` 参数，但 Native 中 `-R` 对应 role；当前值 0 恰好是主播。后续 Go 结构体应命名为 role，而非 render。

### 用户、连接、进程是不同计数

一个 sample 进程可包含多个 `-O` 分隔的连接。stress_meeting.py 又把同一业务用户的音频和视频拆为不同连接；因此“业务用户数”“Native 连接数”“Native 进程数”不能混用。频道数量也应单独记录。

### 编排层不能仅检查参数是否被识别

- 严格检查端口、帧率、声道、采样率、UID 范围、媒体文件和角色/发布关系。
- UID 列表不能把非法输入过滤成空后继续运行；空列表可能扩大为全订阅。
- 长参数使用等号，短参数和值分开。
- 全局参数不允许在同一进程不同连接间表达不同值；需要拆进程或拒绝冲突。
- 每条连接显式携带其自身配置。
- 参数中会出现凭据，应用日志和任务详情需要对 token 做脱敏。

## 尚不能宣称完成的部分

1. 没有对应版本源码，模式枚举的完整合同仍需来源说明；mode=3 的连接切换只作静态确认。
2. VOCS 格式、video-type 的完整作用、AUT 加密组合、SDK 私有参数逐项语义尚未验证。
3. 媒体格式、大小流组合、真实发布订阅、鉴权失败和重连表现需要小规模 RTC 集成测试。
4. 当前 180 个检查只覆盖解析和配置，不构成 180 次有效 SDK 或压力测试。

因此当前状态是：参数入口、别名、默认值、作用域和几条关键执行分支已核对；所有参数组合在目标 RTC 环境中的行为尚未全部验证。
