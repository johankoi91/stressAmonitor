# 0.12.0 统一 UID 行为与共享频道验证

2026-11-25，A/B/C/D 四节点已升级到 0.12.0。

界面将“创建频道内 UID”改为“频道内 UID 行为/个数”，删除“加入频道内收流 UID”，将“额外加入频道”改为“加入已有频道”。同一行的发流/收流人数统一作用于本机创建和加入的频道。

线上只读计划核对：200 频道、每频道 5 UID、总 1000 PCU。A/B 各创建 100 个频道，每频道 2 发＋1 收；C/D 各加入已有 200 个频道，每频道 0 发＋1 收。C 的名单和 D 的名单分别等于 A/B 创建的完整数组，两台机器之间允许全部 200 个频道重叠，每机内部没有重复。每频道累计 3＋1＋1＝5 UID。

验证包括：

- Go race/vet 与 React、Linux 控制程序、Linux CGO SDK Worker 构建通过。
- 100 组随机共享频道配额验证，检查每机唯一名单、每频道人数、PCU、进程容量及相同配置生成相同结果。
- 部分加入、不同人数的约束匹配、需要回溯的创建端排除、加入端发流、同频道 UID 冲突、错误配额和人为破坏名单均有覆盖。
- 控制流程使用模拟回调验证：创建端 B 未确认入频道前，不启动 C/D；创建端确认后再启动加入端，全部用户就绪后才发送统一音频起始时间。
- 界面检查确认 C 的清单分页包含 A 创建的前段和 B 创建的末段频道，频道表逐项显示 C/D 同时参与及每台机器的 UID 行为。
- 所有节点的控制程序与 SDK Worker 文件摘要匹配本次构建；线上前端匹配构建产物，无浏览器警告/错误或页面横向溢出。

本次未启动媒体压测，未覆盖原保存的 750 UID 场景。配置迁移先以待核对草稿展示，保存后才按统一行为执行。旧 0.11.0 的单接收机器分区规则已被本次界面规则替代。

## 0.12.1 固定进程 UID 分配

字段已改为“单进程分配 UID 数”。新增严格等式与频道分组整除检查，生成后的每个进程也会检查实际连接数完全等于指定数。10×30 和 20×15 对应 100 频道×3 UID 的案例通过；多余空槽、分配不足以及会拆散频道的 12×25 案例被拒绝。随机计划用精确分配参数重新验证，race/vet、前端和 Linux 双程序构建通过。四节点已部署 0.12.1，线上 A/B10×30、C/D10×20 计划逐进程核对通过，程序和前端摘要匹配。界面“计算进程数”验证采用精确除法。本次未启动媒体压测。
