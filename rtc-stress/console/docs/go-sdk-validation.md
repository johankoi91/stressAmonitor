## 尚未达标的部分

A 的 16 核 CPU 在本配置下接近 100%。400 个发送者的 PCM 实时目标为 614.4 Mb/s，实测约 236.3 Mb/s，即 38.5%。10 ms 定时推送在负载下未达到实时速度；发送 API 返回成功和持续收到音频都不能证明满实时发送。因此，本轮确认连接规模和持续编码收流，**全速音频压测尚未达标**。

A 的进程 RSS 合计在开始约 1 分钟时为 5.23 GiB，结束前为 6.41 GiB，约增长 136 MiB/分钟，未在 10 分钟内收敛。期间 A Go heap 合计约 70～85 MiB。B/C RSS 变化较小。本轮未触发 16 GiB 容器停止阈值，不能据此判定长期内存稳定或内存问题已经根治。

## 多 Service 实测限制

分别在独立探针进程两次调用 C agora_service_create() 与公开 C++ createAgoraService()，两种接口每次都返回相同的底层 Service 地址；这不是只在 Go 包层的单例限制。实际 helper 两个 Service 的小规模尝试也检测到同一 native identity，主动终止。

因此当前 SDK 版本不能执行同进程多个独立 Service 的 1000 UID 比较。API 和页面已明确拒绝该布局，不将多个 Go 对象包装同一底层 Service 当作比较结果。若要继续这一分支，需要 SDK 提供支持独立 Service 实例的接口或版本。

## 带宽解释

6 秒 tcpdump 抽样：A UDP 下行 77.51、上行 41.17 Mb/s，B/C UDP 下行约 39.06/39.14 Mb/s。接收量约为 2:1:1，与 800/400/400 路订阅数量相符。整机 Netdata 统计还包含链路开销、其他服务和控制台 HTTP；编码回调统计的是去除传输开销后的负载，两个口径不应直接相等。抓包还包含少量其他 UDP 流量，不能全部归于本任务。原先 A 到 Mac 的 SSH 吞吐测量不能据此解释为所有 RTC 网络限速。
